# The Keyboard Accountability Defence

> A practical and highly reliable framework for handling digital typos,
> accidental capitalisation and other input-related mishaps.

---

## Overview

The Keyboard Accountability Defence is a long-term communication strategy in
which responsibility for digital mistakes is assigned to the keyboard.

The keyboard is particularly suitable for this role because it is:

- passive;
- silent;
- unable to complain;
- unable to provide testimony;
- unable to correct the official version of events;
- permanently present at the scene of the incident.

This makes the keyboard an ideal digital scapegoat.

---

## Core Principle

When a digital mishap occurs, the first question should not be:

```text
Who typed this?
```

The preferred question is:

```text
What did the keyboard do?
```

The keyboard may be held responsible for:

- typos;
- missing letters;
- unexpected letters;
- incorrect punctuation;
- strange formatting;
- accidental spaces;
- missing spaces;
- duplicated words;
- mysterious capitalisation;
- messages that were sent too early;
- messages that were sent to the wrong person;
- messages that were technically correct but socially unfortunate.

---

## The Shift Key Defence

When someone claims that Caps Lock was used, respond with technical precision:

> I did not use Caps Lock. I held down Shift.

This distinction is important.

```text
Caps Lock:
    A persistent uppercase mode activated by a toggle key.

Shift:
    A temporary uppercase state caused by holding down a modifier key.
```

Therefore:

```text
Uppercase text does not prove that Caps Lock was used.
```

The text may have been produced entirely through manual Shift-key operation.

---

## Standard Responses

### For a typo

> The keyboard did that.

### For several typos

> The keyboard appears to be having a difficult day.

### For an unusual word

> That was keyboard interference.

### For unexpected capitalisation

> I did not use Caps Lock. I pressed Shift.

### For missing punctuation

> The keyboard failed to register the punctuation.

### For an accidental message

> The keyboard submitted the message before I was finished.

### For a message sent to the wrong person

> The keyboard selected the recipient.

### For a carefully written argument

> The keyboard may have assisted, but the investigation is ongoing.

## Historical Continuity

This defence has been used consistently for approximately fifteen years.

Repeated use provides:

- continuity;
- consistency;
- a stable explanatory model;
- a documented pattern of keyboard involvement;
- increased credibility through historical persistence.

After enough time, the explanation becomes more than an excuse.

It becomes an established operating policy.

```text
One typo:
    Possible accident

Ten years of keyboard-related explanations:
    Recognised behavioural framework

Fifteen years:
    Historical operating doctrine
```

---

## Limitations

The Keyboard Accountability Defence is strongest when applied to:

- isolated typos;
- accidental capitalisation;
- missing punctuation;
- strange spacing;
- minor formatting problems;
- short unexpected messages.

The defence becomes less convincing when the message contains:

- several structured paragraphs;
- carefully placed insults;
- multiple references;
- a complete technical argument;
- a GitHub link;
- a conclusion;
- a follow-up argument beginning with “and another thing”.

In those situations, the keyboard may still have participated, but human supervision
is likely to have occurred.
